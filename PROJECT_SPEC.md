# Football Data Lab — PROJECT_SPEC_V2

## 1. Цель проекта

**Football Data Lab** — автоматизированная платформа глубокой футбольной аналитики, предиктивного моделирования и автономной генерации экспертного контента для Telegram-каналов.

### Полный сквозной Pipeline

```text
Sportmonks API
      ↓
Go Ingestion & Collectors (Existing Worker)
      ↓
PostgreSQL DB (Authoritative Data Source)
      ↓
Analytics Engine (Standings, Trends, Form, xG, H2H, Key Stats)
      ↓
Prediction Engine (Single & Accumulator Bets, Value Odds, Probability)
      ↓
Content & AI Copywriter Engine (Deterministic Fact Pack → LLM → Telegram Post)
      ↓
Renderer Engine (ViewModel → HTML/CSS → Headless Chromium → PNG 1920px)
      ↓
Autonomous Publisher & Scheduler (Cron/Event Trigger → Queue → Telegram Bot)
      ↓
Publication History & Prediction Settlement Analytics (ROI, Yield, Accuracy)
```

---

## 2. Текущий статус проекта (Что уже реализовано)

Проект содержит зрелую инфраструктуру:

* **Backend**: Go (микросервисная/модульная архитектура, idiomatic Go, чистые интерфейсы);
* **БД**: PostgreSQL с богатой исторической схемой (fixtures, standings, events, odds, statistics, teams, leagues);
* **Data Ingestion**: налаженный сбор данных через Sportmonks v3 API;
* **Единая точка запуска CLI**: `cmd/lab/main.go` с флагом `-task PublishToTelegram` и типами `-type (table|roundResults|roundFixtures|previewMatch|roundDigest)`;
* **Renderer & Шаблоны** (Ultra HD 1920px, dark glassmorphic theme):
  1. `TABLE` — турнирная таблица (20 команд, зоны еврокубков, form, trend, key stats leaders);
  2. `ROUND RESULTS` — результаты тура (2 колонки, крупный счёт, счёт 1-го тайма `1Т`, красные карточки `🟥`, авторы голов, xG, сводка тура);
  3. `ROUND FIXTURES` — анонс следующего тура (Marquee Match of the Week, календарная разбивка по дням, время начала матчей с поддержкой параметризованной таймзоны `Timezone`, позиции клубов, форма, котировки);
* **Интерактивный Telegram Mini App (FDL WebApp)**:
  - **Match Center**: шапка матча с логотипами и счётом, двусторонний таймлайн событий («Обзор»), визуализация расстановки на тактическом поле (4-3-3, 4-2-3-1 с номерами и скамейкой запасных), сравнительная статистика матча, блок H2H;
  - **Интерактивная турнирная таблица**: динамика позиций (▲/▼), форма последних 5 игр, еврокубковые зоны (ЛЧ, ЛЕ, ЛК, вылет);
  - **Интерактивный список результатов тура**: группировка по дням недели, быстрый переход в матч-центр;
  - **Nginx & Cache Control**: настроены заголовки `no-cache, no-store, must-revalidate` для HTML и JSON, исключающие зависание кэша в Telegram WebView;
* **Локализация названий команд**:
  - Поддержка параметров `-l ru`, `-l en`, `-l ua` (по умолчанию `ru`);
  - Извлечение локализованных названий из колонки `provider_teams.locale` (`ru.short` $\rightarrow$ `ru.long` $\rightarrow$ `name`);
* **Текстовые посты Telegram**:
  - Строгое моноширинное вертикальное выравнивание колонок через теги `<code>`;
  - Жирные визуальные акценты в блоке экспресс-статистики тура;
  - Кликабельные deep link ссылки на конкретные матчи в Telegram Mini App.

### Архитектурные ограничения (Остаются неизменными)
* Не изменять без прямой необходимости существующие Sportmonks collectors и migrations;
* Соблюдать строгие слои: `DB → Analytics → Content → ViewModel → Renderer → Publisher`;
* Analytics и Content работают строго через собственную БД;
* Никаких математических или статистических расчётов внутри HTML-шаблонов или Telegram-слоя.

### Блок 1: Таблица расписания и истории публикаций в Telegram

Для исключения дублирования постов, учёта времени выхода, отслеживания статусов и возможности редактирования/удаления сообщений создаётся модуль истории и планирования публикаций.

#### 1.1. Схема таблицы: `telegram_publications`

```sql
CREATE TABLE IF NOT EXISTS telegram_publications (
    id BIGSERIAL PRIMARY KEY,
    
    -- Контекст публикации
    channel_id BIGINT NOT NULL,                  -- ID целевого Telegram-канала / чата
    message_id BIGINT,                           -- ID опубликованного сообщения в Telegram (для reply/edit)
    publication_type VARCHAR(50) NOT NULL,       -- 'table', 'round_results', 'round_fixtures', 'prediction', 'express', 'insight'
    
    -- Привязка к футбольным сущностям
    league_id INT,                               -- ID лиги
    season_id INT,                               -- ID сезона
    round_id INT,                                -- ID тура (если применимо)
    fixture_id INT,                              -- ID матча (для одиночных постов)
    
    -- Контент
    title VARCHAR(255) NOT NULL,                 -- Внутренний заголовок публикации
    text_content TEXT,                           -- Итоговый текст поста (Markdown/HTML для Telegram)
    media_url TEXT,                              -- Путь к сгенерированному PNG на диске / S3
    media_type VARCHAR(20) DEFAULT 'photo',      -- 'photo', 'album', 'text'
    metadata JSONB DEFAULT '{}'::jsonb,          -- Доп. параметры (prompt LLM, токены, параметры рендера)
    
    -- Жизненный цикл и планирование
    status VARCHAR(30) NOT NULL DEFAULT 'draft', -- 'draft', 'scheduled', 'rendering', 'ready', 'published', 'failed', 'cancelled'
    scheduled_at TIMESTAMPTZ,                    -- Запланированное время публикации
    published_at TIMESTAMPTZ,                    -- Фактическое время публикации
    
    -- Ошибки и повторные попытки
    retry_count INT DEFAULT 0,
    error_message TEXT,
    
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_tg_pub_status_scheduled ON telegram_publications(status, scheduled_at);
CREATE INDEX idx_tg_pub_league_round ON telegram_publications(league_id, round_id);
CREATE INDEX idx_tg_pub_type ON telegram_publications(publication_type);
```

#### 1.2. Функционал модуля `publisher/history`:
- **Аудит**: Полная история всех когда-либо отправленных постов;
- **Идемпотентность**: Защита от повторной отправки одинаковых итогов тура или таблиц;
- **Мониторинг**: Логирование ошибок Telegram API (FloodWait, Blocked, Bad Request);
- **Хранение медиа**: Локальный кэш PNG с автоматической ротацией старых файлов.

### Блок 2: Модуль прогнозов, экспрессов и сквозной аналитики исходов

Платформа расширяется подсистемой ведения прогнозов (ординары и экспрессы) с автоматическим расчётом прибыльности (ROI, Yield, WinRate).

#### 2.1. Схема таблицы: `predictions` (Заголовок прогноза / Карточка ставки)

```sql
CREATE TABLE IF NOT EXISTS predictions (
    id BIGSERIAL PRIMARY KEY,
    
    -- Тип ставки
    bet_type VARCHAR(30) NOT NULL,               -- 'single' (ординар) или 'accumulator' (экспресс)
    title VARCHAR(255) NOT NULL,                 -- e.g. "Двойник на субботний тур АПЛ"
    analysis_text TEXT,                          -- Аналитическое обоснование (сгенерировано AI)
    
    -- Финансово-математические показатели
    total_odds NUMERIC(8, 3) NOT NULL,           -- Итоговый коэффициент (произведение для экспресса)
    confidence NUMERIC(4, 2),                    -- Оценка вероятности модели (0.00 - 1.00)
    value_edge NUMERIC(5, 2),                    -- Положительный перевес над линией букмекера (%)
    recommended_stake NUMERIC(5, 2) DEFAULT 1.0, -- Рекомендуемый размер ставки в юнитах (e.g. 1.0u, 2.5u)
    
    -- Статус и расчёт исхода
    status VARCHAR(30) NOT NULL DEFAULT 'pending', 
    -- 'pending', 'won', 'lost', 'refund' (возврат), 'half_won', 'half_lost', 'cancelled'
    
    profit_units NUMERIC(8, 3) DEFAULT 0.000,    -- Чистая прибыль в юнитах (+1.85u или -1.00u)
    settled_at TIMESTAMPTZ,                      -- Время закрытия прогноза
    
    -- Связь с публикацией
    publication_id BIGINT REFERENCES telegram_publications(id) ON DELETE SET NULL,
    
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_predictions_status ON predictions(status);
CREATE INDEX idx_predictions_created ON predictions(created_at);
```

#### 2.2. Схема таблицы: `prediction_items` (Конкретные исходы матчей внутри прогноза)

Для ординара — 1 запись. Для экспресса — 2 и более записей.

```sql
CREATE TABLE IF NOT EXISTS prediction_items (
    id BIGSERIAL PRIMARY KEY,
    prediction_id BIGINT NOT NULL REFERENCES predictions(id) ON DELETE CASCADE,
    
    -- Привязка к матчу Sportmonks
    fixture_id INT NOT NULL,
    league_id INT NOT NULL,
    home_team_id INT NOT NULL,
    away_team_id INT NOT NULL,
    match_starting_at TIMESTAMPTZ NOT NULL,
    
    -- Рынок и выбор ставки
    market_name VARCHAR(100) NOT NULL,           -- '1X2', 'Double Chance', 'Over/Under 2.5', 'BTTS', 'Handicap'
    market_key VARCHAR(50) NOT NULL,             -- Кодовое обозначение для автоматического матчинга
    selection VARCHAR(100) NOT NULL,            -- 'Home Win', 'Over 2.5', 'Yes', 'Away +1.0'
    odds NUMERIC(6, 3) NOT NULL,                -- Коэффициент на момент формирования
    bookmaker_name VARCHAR(50) DEFAULT 'Pinnacle',
    
    -- Фактический результат после свистка
    actual_score_ft VARCHAR(20),                 -- '2:1'
    actual_score_ht VARCHAR(20),                 -- '1:0'
    settlement_status VARCHAR(20) DEFAULT 'pending', -- 'pending', 'won', 'lost', 'refund'
    settlement_details TEXT,                     -- Причина расчёта: e.g. "Тотал голов 3 > 2.5 — Выигрыш"
    
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_pred_items_fixture ON prediction_items(fixture_id);
CREATE INDEX idx_pred_items_status ON prediction_items(settlement_status);
```

#### 2.3. Модуль аналитики эффективности (Settlement & Performance Analytics):
- **Фоновый демон сверки (Auto-settlement worker)**:
  - При переводе статуса матча в `FT` (по таблицам `provider_fixtures` и `provider_fixtures_scores`) демон автоматически рассчитывает статус каждого `prediction_item`.
  - После расчёта всех элементов экспресса автоматически вычисляется общий статус `predictions.status` и `profit_units`.
- **Дашборд эффективности (KPIs)**:
  - **ROI** (Return on Investment) = `(Чистая прибыль / Сумма ставок) × 100%`;
  - **Yield** = средняя доходность на ставку;
  - **Win Rate** = процент зашедших прогнозов;
  - Аналитика в разрезах: по турнирам (АПЛ, Ла Лига и т.д.), рынкам (Тоталы, Исходы, Обе забьют) и диапазонам коэффициентов.

### Блок 3: Автоматизация публикаций в Telegram-канал

Переход от ручного запуска к полностью автономной работе контентной фабрики.

#### 3.1. Триггеры и расписание (Event-driven + Cron Scheduler)

| Тип публикации | Триггер / Время | Генерируемый контент |
| :--- | :--- | :--- |
| **Анонс тура (Upcoming Fixtures)** | За 24 часа до первого матча тура | Инфографика `round_fixtures.png` + аналитический пост от AI |
| **Матч дня / Прогноз (Marquee Match)** | За 4 часа до стартового свистка центрального матча | Карточка матча / Ординар / Экспресс + превью от AI |
| **Результаты игрового дня / тура** | Через 15 минут после завершения последнего матча тура | Инфографика `round_results.png` + сводка событий от AI |
| **Актуальная таблица (Standings)** | Сразу после публикации результатов тура | Инфографика `standings.png` + пост об изменениях позиций |
| **Отчёт по ставкам (Betting Review)** | Утром в понедельник / вторник | Сводный отчёт проходимости прогнозов за тур (ROI, баланс) |

#### 3.2. Архитектура исполнителя (Publisher Daemon):
1. **Scheduler Engine**: Cron-планировщик на Go (проверяет расписание каждую минуту);
2. **State Machine**:
   - `scheduled` → создание задачи рендеринга;
   - `rendering` → вызов Renderer (генерация PNG 1920px);
   - `ready` → генерация текста через AI Copywriter;
   - `publishing` → отправка в Telegram через Telegram Bot API;
   - `published` → фиксация в `telegram_publications`.
3. **Отказоустойчивость**:
   - Retry policy при сетевых сбоях с экспоненциальной задержкой;
   - Оповещение администратора в служебный чат при критических сбоях;
   - Защита от дублей (idempotency token).

### Блок 5: Интеграция коэффициентов букмекерских контор (Bookmaker Odds Integration)

Котировки букмекеров являются важнейшим контекстом для футбольной аналитики, оценки вероятностей и прогнозов.

#### 5.1. Принцип интеграции букмекеров
- Источник данных — существующие таблицы котировок в БД (`provider_odds`, `bk_*`);
- В инфографике отображаются коэффициенты **одной выбранной букмекерской конторы** (по умолчанию **Pinnacle** как эталон маркет-мейкера или локальный партнёр канала, например **Winline**);
- Букмекер указывается явно в виде бейджа/подписи в карточке матча.

#### 5.2. Коэффициенты в матчах следующего тура (Upcoming Fixtures) — MUST HAVE
- **Основная линия 1X2 (П1 — Х — П2)**: компактный аккуратный блок под временем матча;
- **Матч тура (Marquee Match)**: расширенная линия — 1X2, Тотал (ТБ 2.5 / ТМ 2.5) и процентная вероятность исходов модели;
- **Визуальная подсветка фаворита**: коэффициент фаворита выделяется акцентным цветом.

#### 5.3. Анализ: стоит ли показывать коэффициенты в результатах прошедших матчей?
- **Рекомендация и варианты реализации**:
  1. **Вариант А (Чистый спортивно-аналитический)**: Коэффициенты в результатах **не показываются**. Внимание зрителя сфокусировано на счёте, результате 1-го тайма, авторах голов, красных карточках и xG. Это стандарт классических медиа (Sky Sports, Premier League).
  2. **Вариант Б (Беттинг-аналитика и сенсации тура)**: Отображаются предматчевые коэффициенты закрытия (closing odds) с подсветкой зашедшего исхода (например, `1.85 [✓]`), а для крупных неожиданностей (кэф >= 3.50) выводится бейдж `🔥 Сенсация: кэф 4.50`. Это повышает вовлечение в каналах с прогнозами.
- В архитектуре реализуются **оба варианта** через флаг `ShowClosingOdds` во ViewModel.

### Блок 6: Параметризация таймзоны (Timezone Agnostic Formatting)

Для гибкой поддержки аудиторий и каналов в различных географических регионах время начала матчей и генерации отчётов не привязывается жестко к одной зоне:
- **Параметр во ViewModel**: В `RoundFixturesViewModel`, `RoundResultsViewModel` и элементах матчей поддерживается поле `Timezone string` (например, `"MSK"`, `"UTC"`, `"CET"`, `"EET"`, `"GMT+3"`);
- **Динамический рендеринг**: В HTML-шаблонах постфикс часового пояса подставляется строго из переданного параметра: `{{if .Timezone}} {{.Timezone}}{{else if $.Timezone}} {{$.Timezone}}{{end}}`. Если параметр не задан, жестко зашитая аббревиатура не выводится;
- **Конфигурация каналов**: Целевая таймзона задаётся на уровне конфигурации канала / публикации (`config.yaml` / CLI аргументы), а слой подготовки контента приводит метки времени к требуемой зоне до передачи во ViewModel.

### Блок 4: Подготовка текстов публикаций с использованием ИИ (LLM Copywriter)

Интеграция большой языковой модели (DeepSeek / OpenAI / Anthropic / Local LLM) для генерации живых, экспертных и вовлекающих текстов к графическим материалам.

#### 4.1. Фундаментальный принцип работы с ИИ

> **LLM никогда не считает статистику, не выдумывает результаты и не определяет факты самостоятельно.**  
> LLM выступает исключительно в роли профессионального спортивного редактора и копирайтера.

```text
[ Наша БД ]
    ↓
[ Analytics Engine ]
    ↓
[ Fact Pack JSON ] (Проверенные детерминированные факты: счёт, xG, карточки, тренды)
    ↓
[ Prompt Engine ]  (Промпт с ролью, стилем, ограничениями и структурой)
    ↓
[ LLM API ]        (DeepSeek / GPT-4o / Claude 3.5 Sonnet)
    ↓
[ AI Editor Validation ] (Проверка на соответствие фактам и длине)
    ↓
[ Telegram Post ]  (Идеальный текст с форматированием, эмодзи и структурой)
```

#### 4.2. Структура Fact Pack (JSON-пакет фактов для LLM)

```json
{
  "post_type": "round_results",
  "league": "Premier League",
  "season": "2023/2024",
  "round": 28,
  "stats": {
    "total_goals": 28,
    "avg_goals": 2.8,
    "home_wins": 5,
    "draws": 3,
    "away_wins": 2,
    "red_cards": 3
  },
  "top_match": {
    "fixture": "Manchester City vs Liverpool",
    "score": "2:2",
    "ht_score": "1:1",
    "xg": "2.45 - 2.10",
    "key_events": ["Холанд 15', 54'", "Салах 38'", "Диас 76'"]
  },
  "dramas": [
    "Удаление Джексона на 88' у Челси в дерби с Арсеналом",
    "Волевая ничья Борнмута с дублем Соланке"
  ],
  "table_context": {
    "leader": "Arsenal (64 pts)",
    "closest_pursuer": "Liverpool (64 pts)"
  }
}
```

#### 4.3. Требования к промптам и стилю контента:
- **Tone of Voice**: Экспертный, динамичный, современный футбольный язык (без «воды» и шаблонных штампов);
- **Форматирование**: Поддержка Telegram MarkdownV2 / HTML (жирные заголовки, списки, акцентные эмодзи `⚽`, `🔥`, `📊`, `🟥`);
- **Структура поста**:
  1. Яркий хук/заголовок;
  2. Главная интрига или триллер тура;
  3. Краткий разбор ключевых результатов (с xG и нюансами);
  4. Положение в таблице;
  5. Вовлекающий вопрос к аудитории (Call to Action).
- **Запасной вариант (Fallback)**: При недоступности LLM API или задержке ответа более 10 секунд публикация отправляется со стандартным детерминированным шаблоном текста.

### Блок 7: Интерактивное расписание тура (Upcoming Fixtures) с котировками 1X2 и Pre-Match режим в Mini App

Расписание следующего тура приводится к единому интерактивному формату, связывающему лаконичный пост в Telegram и предматчевый Match Center в Mini App.

#### 7.1. Текстовый пост расписания в Telegram
- Формируется за 24–36 часов до первого матча тура.
- Моноширинное вертикальное выравнивание (`<code>`).
- Формат строки: `• 14:30  Арсенал — Челси  [ 1.85 · 3.60 · 4.20 ]`, где котировки 1X2 являются кликабельными гиперссылками на конкретный матч в Mini App.
- Блок «Матч тура» с вероятностями исходов модели и xG-прогнозом.
- Инлайн-кнопки: `[ 📱 Все матчи тура в Mini App ]` и `[ 📊 Турнирная таблица ]`.
- Автоматическое закрепление поста (Silent Pin) в канале на время уикенда как главного навигатора тура.

#### 7.2. Pre-Match экран в Telegram Mini App
Для еще не начавшихся матчей активируется предматчевый режим со следующими табами:
- **H2H (История личных встреч)**:
  - Сводка из БД: всего матчей, победы A / ничьи / победы B, средний тотал голов.
  - Список до **10 последних очных матчей** с датой, турниром, счётом и xG.
- **Статистика (Сравнительный профиль команд)**:
  - Переключатель периода: `[ За последние 5 туров ]` / `[ За весь сезон ]`.
  - **Топ-3 Hero-метрики первого экрана**:
    1. ⚡ **xG за матч** — созданная атакующая опасность (качество моментов);
    2. 🛡️ **xGA за матч** — допущенная опасность у своих ворот (надежность обороны);
    3. ⚽ **Среднее количество голов** — забитые и пропущенные мячи (в сравнении с xG выявляет перевес/невезение).
  - **Вспомогательные метрики**: Обе забьют (BTTS %), Тотал больше 2.5 (%), Удары в створ за матч, Владение мячом (%), Угловые, Желтые карточки.
- **Составы (Lineups & Sidelined)**:
  - За 24ч – 75 мин до игры: плашка `⏳ Официальные составы появятся за 60 минут` + ориентировочные составы + блок «Травмированные и дисквалифицированные» (sidelined).
  - За 60 минут: автоматический рендеринг тактического поля 4-3-3 / 4-2-3-1 с подтвержденными составами и скамейкой.

### Блок 8: Селектор лиг в Telegram Mini App (Масштабирование на 15+ лиг)

Для поддержки 15+ европейских лиг без перегрузки основного Telegram-канала реализуется единый мульти-лиговый комбайн:
- **Header Selector**: кликабельный бейдж в шапке Mini App с каруселью топ-лиг.
- **Bottom Sheet шторка**: полный каталог турниров, разбитый на «Топ-турниры» и «Европейские лиги» с флагами и статусом текущего тура.
- **Бэкенд-каталог**: файл `/media/active_leagues.json` с метаданными всех активных турниров.
- **Single Page Application (SPA)**: мгновенное переключение лиги за ~150 мс без перезагрузки веб-страницы.
- **Запоминание выбора**: сохранение любимой лиги пользователя в `localStorage`.
- **Поддержка Deep Links**: переход из любого поста сразу открывает нужную лигу и матч.

### Блок 10: Управление контентной лентой (Macro-posts vs Micro-data, новости и видео)

- **Принцип «Якоря + Mini App»**:
  - В канал публикуются только 4–7 качественных макро-постов в день (без спама по 150 матчам).
  - Пост расписания тура закрепляется в пятницу вверху канала.
  - По ходу уикенда новости и видео голов выходят новыми сообщениями в ленту.
  - После завершения тура выходит итоговый пост «Результаты тура + экспресс-статистика», снимающий или обновляющий закреп.
  - Вся детальная статистика матчей в реальном времени живет внутри Mini App.

```bash

```
